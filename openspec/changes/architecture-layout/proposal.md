## Why

사용자가 앱에 처음 접속할 때 명확한 진입점이 필요합니다. 인증 없이는 메인 기능에 접근할 수 없도록 보호하고, 인증 후 일관된 레이아웃과 직관적인 메뉴 네비게이션으로 사용자 경험을 향상시킵니다. 이는 모든 하위 기능의 기초가 되는 필수 아키텍처입니다.

## What Changes

- **가상 로그인 진입점**: ID/PW 기반 Mock 로그인 페이지 추가 (초기 개발 최적화)
- **전역 레이아웃 구조**: 상단 메뉴, 좌측 서브메뉴, 본문 영역의 3단 레이아웃 구현
- **메뉴 라우팅 시스템**: 상단 메뉴 선택 시 좌측 서브메뉴 동적 업데이트 및 본문 라우팅
- **인증 상태 관리**: 전역 로그인 상태 관리 및 auth guard를 통한 접근 제어
- **UI/UX 디자인 기준**: 미니멀리즘(극도로 단순함), 모노톤 컬러(무채색 중심) 스타일 적용

## Capabilities

### New Capabilities

- `user-auth-login`: 사용자 가상 로그인 기능 (고정 계정: ID gagamel / PW 1234)
- `global-layout`: 앱의 기본 레이아웃 구조 (상단 메뉴, 좌측 서브메뉴, 본문)
- `menu-navigation`: 메뉴 기반 라우팅 및 화면 전환 시스템
- `auth-guard`: 미인증 사용자의 메인 레이아웃 접근 차단

### Modified Capabilities

(없음 - 신규 프로젝트 단계)

## Impact

- **전체 앱 구조의 기초**: 모든 페이지/기능이 이 레이아웃 위에서 구현됨
- **상태 관리**: 전역 인증 상태 관리 시스템 필수
- **라우팅**: Firebase Navigation 또는 GoRouter 기반 라우팅 구조
- **UI 컴포넌트**: 메뉴, 버튼, 입력창 등 기본 컴포넌트는 모노톤 디자인 적용
- **Flutter 기본 설정**: MaterialApp, Navigator, State Management (provider/riverpod) 필수
